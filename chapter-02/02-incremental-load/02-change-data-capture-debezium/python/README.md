# Change Data Capture - Debezium

All the components (dataset generator, PostgreSQL, Apache Kafka, Kafka Connect with Debezium, Apache Spark job) run in
Docker containers; you don't need a local Python environment or JDK. The Apache Spark job reaches Apache Kafka at
`kafka:9092` through a shared Docker network (`dedp_ch02_cdc_debezium`) created by the stack from the first step.

1. Generate the dataset and start the containers:
**⚠️ If you replay the demo, stop the Apache Spark job first (see the Cleanup section); it's attached to the network managed by this stack and fails when Apache Kafka gets recreated**
```
cd docker/
docker-compose down --volumes; docker-compose up
```
2. Register the Kafka Connect consumer that will stream PostgreSQL records to Apache Kafka, in a new terminal opened in
this demo's directory (the command retries until Kafka Connect accepts connections):
```
cd docker/
docker exec -i cdc_kafka_connect curl -i --retry 10 --retry-connrefused --retry-delay 3 -X POST -H "Accept:application/json" -H  "Content-Type:application/json" http://localhost:8083/connectors/ -d @- < register-postgresql-connector.json
```
3. Open the [visits_stream_processor.py](visits_stream_processor.py)
* it's a classical Structured Streaming consumer to process created (`filter('visit.payload.op = "c"')`) records
  and aggregate them to 30-seconds windows
4. Run the `visits_stream_processor.py` in a new terminal opened in this demo's directory; you should see the windows printed in the console:
**⚠️ The stack from the first step must be running; it creates the Docker network used by the job**
```
cd docker/stream-processor
docker-compose down --volumes; docker-compose up --build
```
The first run builds the image (it downloads PySpark and the Apache Kafka connector jars) and can take a few minutes.
5. Run Apache Kafka consumer to see the records generated by the Kafka Connect:
```
docker exec -ti docker_kafka_1 kafka-console-consumer.sh \
    --bootstrap-server kafka:9092 \
    --from-beginning \
    --property print.key=true \
    --topic dedp.dedp_schema.visits
```

## Cleanup
Run from this demo's directory and stop the stacks in the reverse order (the Apache Spark job is attached to the network of the first stack, so it must go first):
```
(cd docker/stream-processor && docker-compose down --volumes)
(cd docker && docker-compose down --volumes)
```
